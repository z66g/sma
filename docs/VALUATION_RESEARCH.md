# 적정가치 리서치 지침 (Valuation Desk · 애널리스트 세션용)

기계적 모델은 재무제표 숫자만 본다. 이 리서치의 임무는 **숫자에 없는 것** — 사업모델, 경영 계획, 실제 실행 성과, 뉴스,
성장 가능성 — 을 읽고, 그것을 **검증 가능한 시나리오 가정**으로 번역하는 것이다. 계산은 엔진이 한다.
리서치가 할 일은 "왜 이 성장률·이 마진인가"에 근거를 대는 것이다.

```
python3 valuation.py prepare {T} --out WORK_DIR      # 패키지: 재무 다이제스트 · 기계적 기준선 · SEC 링크 · 템플릿
(조사 · WORK_DIR/{T}_research.json 작성)
python3 valuation.py publish {T} --research WORK_DIR/{T}_research.json --dry-run   # 검증 + 결과 미리보기
python3 valuation.py publish {T} --research WORK_DIR/{T}_research.json             # 발행
```

## 1. 조사 순서 (건너뛰지 말 것)

| # | 무엇을 | 어디서 | 확인할 것 |
|---|---|---|---|
| 1 | **사업모델** | 최근 10-K(또는 20-F)의 Business · Segment 주석 | 무엇을 누구에게 팔고 어떻게 돈을 버는가. 부문별 매출 비중·성장·마진. 고객 집중도. 경쟁 우위의 원천과 지속성 |
| 2 | **실제 성과** | 최근 10-Q + 직전 4~8개 분기 실적발표(8-K item 2.02 첨부) | 가이던스 대비 실적(상회/하회 이력), 마진 추세, 현금 전환, 수주잔고·RPO, 일회성 항목. 숫자가 이야기를 뒷받침하는가 |
| 3 | **경영 계획** | 실적발표 자료·콘퍼런스콜·인베스터데이·8-K | 가이던스, 장기 재무 목표, 증설·CAPEX, 제품 로드맵, 대형 계약, M&A, 자금 조달 계획 |
| 4 | **뉴스·이벤트** | 최근 30~90일 뉴스, 8-K, Form 4 | 가정을 바꾸는 것만: 계약·규제·소송·경쟁사 발표·경영진 교체·내부자 매매 |
| 5 | **산업 맥락** | 경쟁사 실적·산업 자료 | 시장 규모와 성장률, 점유율, 가격 추세, 경쟁사의 마진 수준(목표 마진의 상한 근거) |

- 1차 자료(SEC 공시, 회사 IR)를 먼저 읽고, 뉴스·2차 자료는 보강용으로 쓴다. SEC 문서는 `curl -H "User-Agent: ..."` 로 직접 받을 수 있다.
- 접속이 막힌 사이트가 있으면 다른 출처로 넘어간다. 원문을 열지 못하고 검색 요약으로만 확인한 사실은 그렇게 표시하고, 핵심 가정이 거기에 걸려 있으면 `confidence` 를 낮춘다.
- **기억에 의존하지 않는다.** 모든 사실은 이번 조사에서 확인한 출처(URL·날짜)가 있어야 한다. 확인하지 못한 것은 "확인 불가"라고 쓴다.
- 패키지의 '기계적 기준선'을 먼저 읽고, 그것이 **무엇을 놓쳤는지**를 찾는 것이 출발점이다 (예: 인수 효과로 왜곡된 과거 마진, 가동 전 설비, 아직 매출이 없는 사업).

## 2. 시나리오 작성 규칙

세 시나리오는 서로 다른 **세계**여야 한다 — 같은 이야기에 숫자만 ±10% 한 것은 시나리오가 아니다.

| 필드 | 뜻 | 규칙 |
|---|---|---|
| `story` | 이 시나리오가 실현되는 조건 | 무엇이 일어나야 하는가를 구체적으로 (계약·점유율·가격·규제) |
| `prob` | 발생 확률 | 합 1.0. 근거 없이 25/50/25 로 두지 말 것 — 실행 이력과 현재 증거에 맞춘다 |
| `rev_growth` | 향후 연도별 매출 성장률 (NTM 기준, 3~10개) | 가능하면 부문별로 쌓아서 합산. 명시한 마지막 해 이후는 엔진이 영구성장률로 감쇠 |
| `target_margin` | 도달할 **GAAP 영업이익률** | 주식보상은 비용이다(Non-GAAP 마진 금지). 동종 최고 수준을 넘으면 근거 필수 |
| `margin_year` | 목표 마진 도달 연차 (1~10) | 경영진 목표 시점 또는 설비·제품 램프 일정에 맞춘다 |
| `wacc_adj` | 할인율 가감 (±3%p 이내) | 기본 0. 사업 위험이 기계적 베타에 반영되지 않았다고 판단할 근거가 있을 때만 |
| `s2c` | Sales-to-Capital (선택) | 자본집약도가 과거와 달라질 명확한 이유가 있을 때만 |
| `capex_pct` (+`da_pct`, `nwc_pct`) | 명시적 현금흐름 빌드 (선택) | Finbox 식: FCF = NOPAT + D&A − CAPEX − 순운전자본 증가. `capex_pct` 는 매출 대비 CAPEX(숫자 또는 연도별 목록), `da_pct` 는 D&A(숫자 또는 연도별 목록 — 인수 무형자산 상각이 줄어드는 일정이 공시돼 있으면 연도별로; 마지막 값이 영구 수준이므로 유지 CAPEX 에 맞는 값으로 끝낼 것), `nwc_pct` 는 매출 증가분 대비 순운전자본. **회사가 CAPEX 계획을 공시했거나 자본집약도가 과거와 달라질 때** `s2c`·`extra_investment` 대신 쓴다(셋을 섞지 말 것). 마지막 해 비율이 영구히 유지된다고 계산되므로 마지막 값은 유지 수준으로 둔다 |
| `tax_rate` | 장기 세율 (선택, 0.05~0.35) | 기본은 엔진이 max(유효세율, 21%)로 수렴. 구조적으로 다른 세율의 근거(관할·세제)가 있을 때만 |
| `fail_prob` | 자금조달 실패 확률 (선택) | 현금 소진 기업: 조달 계획·현금 여력을 확인했으면 명시. 같은 위험을 `wacc_adj` 로 또 올리지 말 것(이중 반영) |
| `extra_investment` | 연도별 추가 투자 유출 (달러, 선택; 엔진이 이미 잡는 재투자·감가상각을 뺀 **초과분**. 여기 넣은 자산의 감가상각을 목표 마진에서 또 빼지 말 것) | 매출보다 **앞서** 집행되는 투자(위성망·공장·광산 증설). 엔진의 재투자는 매출 증가 시점에 잡히므로, 회사가 밝힌 CAPEX 계획 중 그 이상분을 연도별로 적는다 |
| `value_per_share` + `value_basis` | 직접 산출 | **금융·REIT** 는 필수(P/B-ROE, 초과이익, P/FFO 등으로 계산해 방법·입력값 기재). 그 외에는 쓰지 않는다 |

- **기본(base)은 컨센서스의 복사본이 아니다.** 컨센서스와 같게 두면 그 이유를, 다르게 두면 어디서 왜 다른지를 `valuation_notes` 에 쓴다.
- **현재가가 맞으려면**: 적정가와 현재가가 크게 다르면, 현재가를 정당화하는 조건(언제까지 매출·영업이익이 얼마)을 역산해 `valuation_notes` 에 적는다.
  괴리를 보고만 하지 말고 설명한다.
- **현재 주가에 맞추지 않는다.** 시나리오는 주가를 보지 않고 쓴다. dry-run 결과가 주가와 크게 달라도 가정을 주가 쪽으로 조정하지 말 것 —
  고치는 것은 오류(단위·이중 계산·근거 없는 숫자)뿐이다. 애널리스트 목표가도 입력으로 쓰지 않는다.
- **현실성 점검**: 10년 뒤 매출이 시장 규모·점유율로 설명되는가? 목표 마진이 업계 최고 수준 이내인가? 성장에 필요한 자본을 조달할 수 있는가?

### 자주 틀리는 처리
- **주식보상·고객 워런트**: 매출 차감이나 비용으로 인식되는 것은 **GAAP 마진에만** 반영한다. 같은 것을 `extra_dilution_pct` 에 또 넣으면 이중 계산이다.
  `extra_dilution_pct` 는 손익에 잡히지 않는 희석(내가격 전환사채, 확정된 증자·주식 대가)만.
- **종결 전 인수·합병**: 종결 전에는 **단독 기준**으로 평가하고, 거래 조건(교환비율·종결 시기·해지 수수료)과 가치 영향(상대 기여도 vs 지분율)은
  `plans`·`risks`·`valuation_notes` 에 적는다. 주식수만 늘리고 피인수 회사의 현금흐름을 빼먹는 식의 부분 반영은 하지 않는다.
- **유한한 사업권**(광업권·특허·양허 만료): 영구성장 가정이 맞지 않으면 `terminal_growth` 를 낮추고 근거를 적는다.
- **지분법이익·기업 이자**: 패키지의 영업이익(Yahoo 표준화)은 지분법이익을 뺀 값이다. 회사가 지분법이익을 영업이익에 넣어 보고하면 시나리오 마진에 포함하고 그 투자 장부가는 `nonop_assets` 에 넣지 않는다(둘 중 하나만).
  금융자산이 큰 회사는 매출·영업이익에 든 기업 현금 이자와 엔진이 따로 더하는 현금이 겹치지 않게 마진에서 이자를 뺀다.
- **인수자금 선조달·통과 항목**: 인수 종결 전 발행한 채권과 그 대금(제한현금)은 상쇄하고, 청산 예치금·고객 수탁자산처럼 자산·부채가 같은 통과 항목은 제외한다.
- **일회성 손익**: 패키지의 ⚠ 표시(매각이익 등)를 확인하고, 시나리오 마진은 반복 가능한 영업이익 기준으로 쓴다.
- **회계연도 가이던스 → NTM**: `rev_growth` 1년차는 TTM 종료 시점부터 12개월이다. 패키지의 'NTM 환산'을 기준점으로 삼는다.

### 신사업 옵션 (`options`)
아직 의미 있는 매출이 없어 시나리오 매출에 넣을 수 없는 사업만 해당한다 (자율주행, 신약 파이프라인, 위성망 등).
- `value_per_share` = 성공 시 그 사업의 가치를 **현재가치로 할인**해 주식수로 나눈 값. `basis` 에 계산식(시장 규모 × 점유율 × 마진 × 배수 ÷ 할인)을 적는다.
- `prob` = 성공 확률. 기술·규제·경쟁 단계의 증거로 정한다.
- **이중 계산 금지**: 옵션에 넣은 사업의 매출은 시나리오 `rev_growth` 에서 뺀다.
- 옵션의 `value_per_share` 는 `adjustments.shares`(지정했다면)와 **같은 주식수**로 나눈다. `basis` 에는 [사실]과 [가정]을 구분해 적고,
  '명백히 성공한 경우'의 가치(천장)도 함께 적는다.
- 신사업 투자는 성공 여부와 무관하게 집행된다 → 투자는 모든 시나리오의 `extra_investment` 에, 옵션에는 성공 시 **추가로** 필요한 자본만 뺀다.
- 옵션가치가 적정가의 25% 를 넘으면 불확실성 등급이 자동으로 내려간다 — 숨기지 말고 그대로 둔다.

## 3. 결과물 필드

| 필드 | 내용 |
|---|---|
| `thesis` | 2~4문장: 이 회사의 가치를 결정하는 핵심 변수와 현재 증거가 가리키는 방향 |
| `business` | `summary`, `segments[{name, revenue_share, growth_view, margin_view}]`, `moat`, `moat_rating` (NONE/NARROW/WIDE) |
| `performance` | `summary`(최근 실적이 계획대로 가고 있는가), `guidance`(최신 가이던스 원문 수치), `execution_rating` (WEAK/MIXED/STRONG) |
| `plans[]` | `{item, timing, impact}` — 가정에 반영한 경영 계획 |
| `news[]` | `{date, headline, impact: POS/NEG/NEU, why}` — 가정을 바꾼 것만 |
| `risks[]`, `catalysts[]` | 약세·강세 시나리오로 가는 구체적 사건 |
| `scenarios`, `options`, `adjustments` | §2. `adjustments.nonop_assets`(달러: 지분투자·보유 암호화폐·**제한현금** 등 엔진의 현금에 안 잡힌 자산), `extra_dilution_pct`(전환증권·예정 증자), `shares`(희석 주식수 — 엔진 주식수(시가총액÷주가)가 미획득 성과주를 포함하거나 발행 예정 주식을 빠뜨릴 때, 10-Q 표지·희석 가중평균 근거로), `debt_like_liabilities`(달러: 연금 부족분·확정된 소송 배상 등 엔진 부채에 없는 부채성 항목 — 차감), `operating_leases_in_debt`(달러: 엔진 부채에 포함된 운용리스 부채 — 리스료가 이미 영업이익에서 빠지므로 되돌린다), `minority_economic_share`(0~0.9: 연결 이익·가치 중 소수주주 몫 — 자회사 지분이 커서 **장부 비지배지분이 경제적 몫을 크게 밑돌 때**. 최근 3년 '비지배지분 귀속 순이익 ÷ 연결 순이익'과 지분율로 근거 제시), `minority_in_share_count`(true: Up-C 구조처럼 비지배지분 보유자가 이미 주식수에 포함된 경우 — 엔진의 비지배지분 차감을 되돌린다), `note`(근거) |
| `valuation_notes` | 컨센서스·기계적 기준선과 다른 지점과 이유, 확인하지 못한 것 |
| `confidence` | HIGH(1차 자료로 대부분 검증) / MEDIUM / LOW(핵심 가정이 추정) |
| `sources[]` | `{title, url, date}` 최소 6개, SEC 공시 포함 |

모든 서술은 한국어. 숫자는 소수(0.25 = 25%).

## 4. 발행 전 검증 (`publish` 가 자동 수행)

발행이 거부되는 경우: 출처 6개 미만 · 확률 합 ≠ 1 · 시나리오 설명 누락 · 범위를 벗어난 성장률/마진 · 근거 없는 옵션.
경고(발행은 됨): 시나리오 가치 순서 역전, SEC 출처 없음. 경고가 나오면 가정을 다시 본다.

발행 후 리서치는 `state/valuation/research/{T}.json` 에 보존되고, 재무·주가가 바뀌면 `valuation.py refresh` 가 같은 가정으로 다시 계산한다.
**리서치는 실적 발표 후 다시 써야 한다** — 100일이 지나면 SMA 에 '갱신 필요'로 표시되고 불확실성이 한 단계 올라간다.
